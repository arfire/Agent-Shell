# Ash 使用手册

Ash 是基于 [Tabby](https://github.com/Eugeny/tabby) 开发的终端工具。你可以像平常一样连接服务器、输入命令，也可以用中文让 Agent 帮你完成任务。

本手册对应当前源码版本。旧版安装包的按钮和功能可能不同。

## 1. 第一次使用

### 启动程序

使用 Windows 便携版时，先解压压缩包，再运行其中的程序。不要直接在压缩包中运行。

如果从源码启动，请按 [README 的启动步骤](../README.md#启动) 操作。

### 添加服务器

1. 点击设置图标，打开 **Profiles & connections（配置与连接）**。
2. 点击 **New → New profile（新建配置）**，选择 SSH。
3. 填写名称、服务器地址、端口和用户名，设置密码或密钥登录方式。
4. 保存后，在左侧 **服务器** 面板找到它。
5. 双击服务器名称，或点击旁边的启动图标，打开连接。

服务器面板保存的是常用连接配置，方便以后快速连接。

### 配置 Agent

打开 **设置 → AI → 模型连接**，填写：

| 字段 | 填什么 |
| --- | --- |
| API Base URL | 模型服务提供的 API 地址 |
| API Key | 模型服务提供的密钥 |
| Model | 模型名称，也可以点击 Models 获取列表 |

点击 **检查模型可用性**，查看普通回复、流式输出、工具调用、结果回传四项结果。全部通过后点击 **保存**。当前版本保存后生效，不需要重启。

其余参数不确定时，保留默认值即可。不使用 Agent 时，无须配置模型。

### 模型接口需要支持什么？

当前 Ash 使用 **OpenAI 兼容的 Chat Completions 协议**。这里说的是接口格式，不要求模型必须来自 OpenAI。

模型服务和所选模型需要同时满足以下要求：

| 要求 | 简单说明 |
| --- | --- |
| Chat Completions | 提供 `/chat/completions` 接口，能够接收对话消息 |
| 流式回答 | 支持 `stream: true`，通过 SSE 逐段返回回答 |
| 工具调用 | 支持 `tools`、`tool_choice: "auto"`，并在流式回答中返回 `tool_calls` |
| 工具结果回传 | 能接收工具执行结果，并继续回答或执行下一步 |

**只支持文字聊天还不够。** Agent 执行命令、请求你补充信息，都依靠工具调用。仅把命令写在回答里，不等于调用了工具。

API 地址填写接口的**基础地址**，不要填写完整的聊天接口。例如服务商给出的聊天接口是：

```text
https://api.example.com/v1/chat/completions
```

那么 API Base URL 应填写：

```text
https://api.example.com/v1
```

以上只是地址示例，请换成你的服务商地址。Ash 会自动在末尾追加 `/chat/completions`。如果服务商的地址不含 `/v1`，也不要自行添加。

有密钥时，Ash 使用 `Authorization: Bearer ...` 发送。无需认证的本地服务可以留空 API Key。目前设置页不支持自定义请求头或单独填写其他认证字段。

“Models”按钮另外使用 `/models` 接口。服务商不提供模型列表时，可以直接手动填写模型名称，不影响聊天接口的使用。

目前没有直接接入 Responses、Anthropic Messages、Gemini 原生等其他协议。使用这些服务时，需要服务商或网关提供上述 Chat Completions 兼容接口。

**“检查模型可用性”会依次检查四项能力**：普通回复、流式输出、工具调用和结果回传。每项都会显示通过或失败的原因。检查使用本地模拟工具，不连接 SSH，也不执行服务器命令；会发起少量模型请求，可能消耗额度，可以随时取消。全部通过表示基本接口可用，实际任务效果仍取决于模型能力。

如果接口提示“不支持参数”，请注意：实际 Agent 请求会发送 `temperature`；普通回复检查还会发送 `stream: false`。目前没有在设置中关闭这些参数的选项，需要所用接口能够接受它们。

## 2. 在终端中使用 Agent

终端底部的模式按钮可以在 **Shell 模式** 和 **Agent 模式** 之间切换。

| 模式 | 用法 |
| --- | --- |
| Shell 模式 | 所有输入交给服务器，和普通 SSH 终端一样 |
| Agent 模式 | 在可以输入新命令时，按 Enter 自动判断：命令交给 Shell，日常语言交给 Agent |

例如，输入下面的命令可以查看当前目录：

```sh
pwd
```

也可以直接输入任务：

```text
帮我看看磁盘空间主要被哪些目录占用了，先不要删除文件。
```

Agent 的回答和命令输出都显示在同一个终端中，可以向上滚动、选择和复制。

### 指定这次输入交给谁

在 Agent 模式下，默认快捷键如下：

| 操作 | 作用 |
| --- | --- |
| Enter | 自动识别并提交 |
| Shift+Enter | 把当前输入直接交给 Agent |
| Ctrl+Enter | 把当前输入直接交给 Shell |
| 底部“发送给 Agent” | 与 Shift+Enter 相同 |
| 底部“发送到 Shell” | 与 Ctrl+Enter 相同 |

**Shift+Enter 不是换行键。** 需要提交多行内容时，可以先在编辑器中写好，再完整粘贴到终端，选择提交方式。

如果识别错了，用指定发送方式即可。快捷键可以在 **设置 → AI → 命令识别** 中修改。

### 补全、历史命令和交互程序

尚未提交的 Agent 草稿保留在本地，可以使用方向键、Home、End、Delete 和退格编辑。

输入为空时，Tab、上下键或 Ctrl+R 会转交远端 Shell，用于补全和查看历史。已识别的命令在末尾按 Tab 也可以进入 Shell 补全；普通任务文字中的 Tab 保留在草稿中，Ctrl+R 会提示先处理当前草稿。

转交 Shell 后，后续编辑由 Shell 处理。出现新的命令提示符后，才重新自动识别。

运行 Vim、top、less 等程序时，按程序原来的方式操作。退出并回到命令提示符后，可以继续使用 Agent。

## 3. 审批、密码输入和停止

需要你操作时，终端底部会临时出现操作区。它用于审批命令、填写密码或补充信息，回答仍然显示在终端中。操作区绑定当前 SSH 标签页和本轮任务，其他窗口不显示，也不能替它审批或提交信息。

- **命令审批**：查看命令及用途，点击“允许执行”或“拒绝”。执行前可以编辑命令。
- **拒绝命令**：只取消这条命令，Agent 会收到“未执行”的结果并继续分析。后续命令仍按规则审批；要结束整个任务，请点击“停止 Agent”。
- **危险命令**：当前权限要求审批时，先点击“允许执行”，再点击“确认执行危险命令”。
- **密码或 Token**：在底部的敏感输入框填写并提交。
- **补充信息**：回答 Agent 的问题后点击“提交”。
- **停止任务**：点击“停止 Agent”。已经完成的操作不会自动撤销。

Agent 运行时切回 Shell 模式会停止 Agent 继续行动，但正在执行的远端命令可能继续运行。需要中断远端命令时，可以在终端按 Ctrl+C；已经完成的操作不会撤销。

### 选择执行权限

在 **设置 → AI → 执行权限** 中选择默认档位：

| 档位 | 实际效果 |
| --- | --- |
| 按配置执行 | 按风险规则处理：安全命令自动执行，修改类命令确认一次，危险命令确认两次，禁止命令拦截 |
| 帮我批准 | 自动批准单次确认的命令；危险命令仍需两次确认，禁止命令拦截 |
| 完全放行 | 自动批准单次和双次确认的命令；禁止规则和凭据访问限制仍然生效 |
| 放手一搏 | 取消 Ash 对 Agent 命令的审批、禁止规则和敏感文件访问限制 |

前三档会阻止 Agent 主动读取已知凭据文件、导出敏感配置或绕过这些限制。需要密码时，通过本地敏感输入框提供。详细边界见 [Agent 凭据保护](AGENT_CREDENTIAL_SAFETY.zh-CN.md)。

**“放手一搏”允许 Agent 读取配置和凭据，并可能把原始内容发送给模型服务或通过网络传出。** 首次启用会提示这一风险，不保证内容仅限当前会话。所有档位都以当前 SSH 账号执行，不会自动获得管理员权限。

终端底部也能临时调整权限，只对这次连接生效，重新连接后恢复“跟随设置”。切换档位后，尚在等待审批的命令不能沿用原授权执行；后续命令按新档位处理。已经发给服务器的命令不会因此撤销。

“完全放行”和“放手一搏”还会自动回答当前授权命令中可识别的是/否提示；密码和其他文本输入仍会显示填写区。

这些审批规则用于 **Agent 发起的命令**。手动发送到 Shell 的命令和文件面板中的 SFTP 操作按各自流程执行。

## 4. 使用左侧面板

### 服务器：管理常用连接

- 双击服务器名称，快速连接。
- 使用顶部搜索框筛选服务器。
- 点击“新建分组”，按用途分类，例如“开发环境”“生产环境”。空分组也可以保留。
- 点击分组旁的铅笔编辑分组；右键服务器，可以将它移到其他分组。

### 文件：浏览和传输远端文件

先选中一个已连接的 SSH 标签页，再点击左侧 **文件**。

- 点击文件夹进入目录，点击文件下载。
- 使用顶部按钮上传文件、上传文件夹或新建目录。
- 双击顶部路径，可以直接输入目录地址。
- 文件发生变化后，可以点击“刷新”。

上传目标是开始上传时文件面板所在的远端目录。上传期间切换目录，不会改变这次上传的位置。进度达到 100% 后，仍需等待远端写入和校验完成；失败时查看提示中的远端路径和原因。

勾选 **跟随终端目录** 后，在终端执行 `cd` 切换目录，文件面板也会跟着切换。它依靠 Shell 上报当前位置，不是读取你输入的文字来猜目录。

如果只想同步一次，点击 **跳转到终端目录**。关闭自动跟随后，可以独立浏览其他文件夹；浏览文件夹不会让终端自动执行 `cd`。

看到“等待 Shell 上报工作目录”时，仍然可以手动浏览文件，等待目录信息可用后再使用跟随功能。

### Agent：查看和继续历史会话

左侧 **Agent** 面板按服务器分组展示会话记录。

- **点击会话名称**：打开对应的 SSH 连接，恢复对话上下文。会话已经打开时，会切换到对应标签页。
- **点击铅笔图标**：修改会话名称，例如“排查磁盘占用”。
- **点击新建**：在当前 SSH 连接中开始一段新的 Agent 对话。
- **勾选全部服务器**：查看其他服务器的会话记录。
- **显示空会话**：查看尚未产生对话记录的会话。
- **点击删除图标，或勾选后批量删除**：确认后删除本地历史记录。正在连接或使用中的会话不能删除。

历史会话直接在对应终端中打开，不再单独显示预览面板。删除历史不会撤销服务器上的操作，删除的记录也无法通过会话列表恢复。

恢复后，终端会展示已保存的对话、SSH 命令和输出，并标明历史记录与本次连接的分界。

**历史命令只展示，不会重新执行。** 恢复的是上下文，不会恢复之前运行的程序或自动回到之前的目录。

如果原来的服务器配置被删除或地址改变，按面板提示选择服务器，再点击“关联并打开”。之后的命令会在所选服务器上执行。

当前 Agent 正在运行时，先停止它，再切换会话。

### 调整面板大小

拖动左侧面板与终端之间的分隔线，可以调整宽度。点击左上角箭头收起面板，可以给终端留出更多空间。

### 记录保存失败怎么办？

如果看到“记录仅保存在内存中”，说明磁盘空间不足、没有写入权限或文件暂时无法写入。应用会自动重试，也可以点击“立即重试”。先解决磁盘或权限问题，等待提示消失后再退出程序；未补写成功的内容在退出后可能丢失。

会话列表文件丢失或损坏时，应用会尝试从历史记录重建列表，并保留损坏文件的备份。新记录可以恢复名称和服务器关联；旧记录缺少服务器信息时，需要手动重新关联。

## 5. 调整 AI 设置

所有 AI 选项都在 **设置 → AI** 中：

| 页面 | 可以调整什么 |
| --- | --- |
| 模型连接 | API 地址、密钥、模型和回答相关参数 |
| 命令识别 | Shell 命令列表、手动发送快捷键 |
| 联网搜索 | 联网模式、SearXNG 地址、搜索模型和请求参数 |
| 执行权限 | 默认权限、命令风险规则 |
| 敏感信息 | 额外脱敏规则；“放手一搏”允许原始命令结果进入模型上下文，不能依靠此页防止外传 |

如果常用命令被识别成 Agent 任务，在“命令识别”的列表里添加命令名，每行一个，例如 `ll`。加入列表只影响输入交给谁，不代表允许 Agent 自动执行它。

如果需要调整审批规则，在“执行权限”里点击“添加命令”，填写命令或子命令，例如 `git status`，再选择风险类型。危险和禁止规则优先。

“试一下规则”可以查看输入会如何识别、Agent 执行时是否需要审批，**不会实际运行命令**。预览结果供参考，实际执行还会结合当前 Shell 检查。

不需要编写正则表达式。高级正则规则仍保留在配置文件中。

设置改好后点击 **保存**。需要撤回自定义规则时，点击 **恢复本页默认**，然后保存。它只恢复当前页的设置，不清除 API 地址、API Key 和模型名称。

### 配置联网搜索

打开 **设置 → AI → 联网搜索**：

1. 选择联网模式。**关闭**不提供联网工具；**按需自动搜索**由 Agent 判断是否需要；**仅明确要求**需要在问题中写明“联网搜索”“查文档”等要求，或提供网页链接。
2. 填写 **SearXNG 服务地址**，例如 `https://search.example.com`。支持内网地址和子路径，不要在末尾添加 `/search`。
3. 确认 SearXNG 服务端已启用 JSON 输出，`search.formats` 包含 `json`。
4. 如果服务入口配置了认证，在 **认证信息（可选）** 中填写完整的 `Bearer …` 或 `Basic …`。没有配置认证就留空；这里不是 SSH 密码，也不是模型 API Key。
5. 点击 **测试搜索连接**。通过后保存设置，再向 Agent 提交一次联网搜索任务。

“测试搜索连接”会从本地 Ash 向 SearXNG 发起实际搜索，用于检查搜索接口。它不调用模型、不执行 SSH 命令，也不等于已经验证完整的 Agent 搜索和阅读流程。

勾选 **使用默认模型** 时，主 Agent 直接搜索并阅读资料。取消勾选后，可以单独填写搜索模型的 API 地址、密钥和模型名称，并检查模型可用性；独立搜索模型仅负责搜索和阅读，不执行终端命令。

高级设置中的搜索语言使用 `auto` 或留空时，跟随服务端默认值；搜索引擎留空时也使用服务端配置。请求从运行 Ash 的电脑发出，不经过当前 SSH 服务器，也不自动继承浏览器代理。

完整的服务端配置、请求限制和排查方法见 [联网搜索说明](agent-web-search.md)。

## 6. 常见问题

**Agent 没有回答？**

先确认底部显示“Agent 模式”，再到“设置 → AI → 模型连接”检查模型可用性。也可以用 Shift+Enter 明确提交给 Agent。

**为什么命令还在等待确认？**

检查终端底部的权限档位。“帮我批准”仍然会确认危险命令；设置里的默认档位也可能被当前连接的临时选择覆盖。即使选择自动批准，密码和缺少的任务信息仍需要你填写。

**为什么 Agent 不能读取配置文件？**

前三档会拦截已知敏感配置和凭据访问。可以让 Agent 改查状态或明确的非敏感字段，需要密码时使用敏感输入框。“放手一搏”会取消这一限制，同时允许读取结果进入模型上下文，使用前请确认可以接受这种传播范围。

**搜索连接超时或返回 HTTP 400？**

超时先检查运行 Ash 的电脑是否能访问服务地址和端口。HTTP 400 表示服务或代理拒绝了当前请求，不能仅凭状态码判断是认证问题；检查服务地址、JSON 输出和服务端日志，并先将语言设为 `auto`、搜索引擎留空再测试。只有服务配置了认证才需要填写认证信息。

**上传后找不到文件？**

查看这次上传的远端目标路径，回到开始上传时的目录并刷新，同时检查文件筛选条件。如果有失败提示，按提示中的路径和原因处理；不要仅根据进度条判断上传成功。

**为什么文件面板没有跟随 `cd`？**

确认选中了对应 SSH 标签页，勾选了“跟随终端目录”，并且当前目录信息已经可用。

**为什么历史里没有更早的命令？**

只能恢复应用实际保存过的记录。旧版本未记录的内容，以及在其他终端中执行的命令，不会自动补入历史。

**为什么看不到手册里的新按钮？**

确认启动的是包含这些功能的版本。从源码更新后，需要重新构建并启动；旧安装包不会随源码自动更新。
