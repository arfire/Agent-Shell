# Agent 凭据保护

Agent 需要密码时必须使用本地密码输入框，不能猜测密码或自行搜索服务器上的凭据。模型接收临时占位符，执行命令时才在本地按 Shell 引号规则替换成实际值；历史和工具结果保留占位符或脱敏文本。

本地执行入口独立检查以下行为，配置中的自动审批、完全放行和自定义规则都不能绕过；审批后修改的命令也会重新检查：

- 访问 `.env`、SSH 私钥、云账号凭据、Docker/Kubernetes 凭据、常见客户端密码文件和命令历史。
- 导出进程环境、容器完整配置、密钥服务内容、云元数据凭据或数据库认证表。
- 搜索密码字段，尝试常见密码，或在登录命令中直接填写密码。
- 使用动态拼接、编码执行等无法直接检查的写法绕过限制。

检查覆盖常见 Shell 包装、引号拼接、输入重定向和内联脚本中的已知路径。部分命令会保守拦截，例如完整 `docker inspect`、`docker compose config` 和配置文件全文读取；可改用状态命令或明确选择非敏感字段。不要改写命令来绕过凭据限制。

核心密码字段、私钥和连接串脱敏始终生效。Agent 命令输出和历史保存会保留未完成的行，避免网络分片或保存定时器将密码拆开后泄漏。用户手动操作的 Shell 仍由用户控制。

这层检查不是服务器上的操作系统沙箱，无法证明任意外部程序、符号链接、未知凭据文件或任意混淆脚本都不会访问秘密。若需要这种强隔离，必须在服务器上使用独立低权限账号和文件访问隔离。已有历史文件不会被本次修复删除或重写。

回归检查：`yarn test:native-agent`；隔离 Electron/SSH 验证：`yarn test:native-agent:ssh`。所有测试使用本机模拟服务和测试凭据。

## 操作授权

旧的 `full` 配置保持可读，但现在对应“逐条确认”，不会再放行修改、危险或禁止命令。`auto` 也只允许有限集合内的只读状态查询自动执行。自定义 SAFE 规则不能把修改或未知命令降为自动执行。

修改代码、启动部署、执行迁移、安装软件、脚本和复合命令必须逐条审批。删除容器或数据卷、重置仓库、删除数据库和改变权限必须二次确认。审批只绑定本次调用的最终命令；命令改写后风险升高会再次审批，执行前还会重新检查规则。拒绝后本条命令不执行，Agent 可以继续分析，后续命令仍按规则审批；点击“停止 Agent”则中断整个任务。远端程序的 y/n 提示也由用户回答，模型不能代答。

这限制了操作权限，不依赖模型自行承认越权。它不自动恢复或修改你服务器上已经发生的数据删除。
