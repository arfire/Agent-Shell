# Agent 凭据保护

四个权限档位都保留任务边界、凭据检查和输出脱敏。Agent 需要密码时使用本地密码输入框；表单显示用途程序和目标。模型只收到随机占位符，执行前按绑定校验程序及目标，任务结束清除绑定。历史、模型请求和工具结果不保留本次输入的密码原值。

## 部署与配置

- 已有 `.env` 由应用直接加载，模型无需获得其中的密码。
- 用户提供项目目录或明确配置文件后，`configuration_status` 只返回指定字段是否配置和经过校验的公开端口、debug 布尔值。服务器需要已有 Python 3；读取器限制大小及真实路径，拒绝越界符号链接。
- 简单的 `docker compose --env-file PATH up -d` 可以启动应用；启动原始输出不进入模型和会话，保留退出码，再检查服务状态或健康接口。
- 缺少密码时，由用户在本地输入，并确认用途程序和目标。凭据命令不允许换目标、跟随重定向、使用代理或外部配置。

检查覆盖已知敏感文件、环境导出、通配符与变量拼接、目录归档及部分混淆写法。审批后的命令也重新检查。公开文档和非敏感状态查询可正常使用；不要改写命令来绕过凭据限制。手动 Shell 和 SFTP 按各自流程执行。

## 操作授权

| 档位 | 命令授权 |
| --- | --- |
| 按配置执行 | 按风险规则自动执行、单次确认、双次确认或禁止 |
| 帮我批准 | 自动批准单次确认；双次确认仍需手动，禁止规则生效 |
| 完全放行 | 自动批准单次和双次确认；禁止规则生效 |
| 放手一搏 | 跳过普通命令审批和自定义禁止规则；首次启用需要确认 |

四档都必须遵守当前用户的任务限制和凭据保护。“放手一搏”仍可能直接删除数据或更改服务器，不能把它当作只读模式。所有档位使用当前 SSH 账号，不会自动获得管理员权限。

设置页选择默认档位，终端底部可为当前连接临时覆盖。改写命令、切换权限和停止任务后不能沿用旧授权；已经提交给服务器的操作不会自动撤销。

## 限制

这层检查不是操作系统沙箱，不能证明任意现有脚本、外部程序、未知秘密或混淆代码都不会访问凭据。模型仍接收任务、连接元数据和允许回传的结果。强隔离需要服务器侧最小权限账号、文件访问隔离或受控操作代理；已有历史不会被本次修复全部删除或重写。

登录密码不会写入最近连接和标签页恢复记录；旧最近连接中的密码会清理。明确勾选记住密码时，仍使用现有保险库或钥匙串。

回归入口：`yarn test:native-agent`、`yarn test:security:boundary-http`、`yarn test:security:real-e2e`、`yarn test:sftp:ui`。真实模型密钥只通过临时进程环境传入，不提交到项目。使用步骤见 [Ash 使用手册](USER_GUIDE.zh-CN.md)。
