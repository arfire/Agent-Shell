# Agent 凭据保护

## 先看结论

在“按配置执行”“帮我批准”和“完全放行”三档中，Agent 需要密码时必须使用本地密码输入框，不能猜测密码或自行搜索服务器上的凭据。输入框显示用途程序和目标，模型接收随机临时占位符，执行前在本地校验程序和目标，执行命令时才按 Shell 引号规则替换成实际值；历史和工具结果保留占位符或脱敏文本。

“放手一搏”则会取消 Ash 的命令审批、禁止规则、任务策略检查和凭据访问限制，允许原始命令结果进入模型上下文。配置和凭据可能发送给模型服务，也可能通过 Agent 执行的网络操作外传。首次启用会提示风险；这不保证内容仅限当前会话，也不会自动获得服务器管理员权限。

## 受限档位：前三档

前三档的本地执行入口独立检查以下行为，自动批准和自定义规则不能绕过；审批后修改的命令也会重新检查：

- 访问 `.env`、SSH 私钥、云账号凭据、Docker/Kubernetes 凭据、常见客户端密码文件和命令历史。
- 导出进程环境、容器完整配置、密钥服务内容、云元数据凭据或数据库认证表。
- 搜索密码字段，尝试常见密码，或在登录命令中直接填写密码。
- 使用动态拼接、编码执行等无法直接检查的写法绕过限制。

检查覆盖常见 Shell 包装、引号拼接、输入重定向和内联脚本中的已知路径。部分命令会保守拦截，例如完整 `docker inspect`、`docker compose config` 和配置文件全文读取；可改用状态命令或明确选择非敏感字段。不要改写命令来绕过凭据限制。

前三档会对进入模型上下文的命令结果进行敏感信息处理。本地历史保存另有脱敏处理，以减少凭据持久化。Agent 命令输出和历史保存会保留未完成的行，降低网络分片将密码拆开后漏检的风险。用户手动操作的 Shell 和 SFTP 仍按各自流程执行。

## 现有配置与登录凭据

- 现有 `.env` 可由应用直接使用。`configuration_status` 只返回用户指定项目中字段是否配置及经过校验的公开端口/debug 标志，不返回密码。服务器需要 Python 3，读取限制大小与真实路径。
- 前三档支持简单的 `docker compose --env-file PATH up -d`，启动原始输出不进入模型或会话，随后查询状态或健康接口；“放手一搏”保留原始输出。
- 前三档的本地凭据绑定 curl/wget 的 HTTP(S) 目标、数据库主机或 sudo 的当前服务器用途，禁止换目标、重定向、代理及外部连接配置。“放手一搏”不要求用途绑定，可继续自主生成密码。
- sudo 验证与操作在同一次 SSH 执行中完成：`printf '%s\n' '占位符' | sudo -S -v && sudo -n 操作`。不要组合 `-k -v`，也不要分两次调用验证与操作；独立执行进程不能复用这一验证状态。
- 普通部署配置支持 heredoc 和 Python `write_text` 写入。Compose 文件可用 `docker compose -f 文件路径 config --quiet` 验证，不输出现有配置中的敏感值。
- SSH 登录密码不写入最近连接和标签页恢复记录，旧最近连接中的密码会清理。明确记住的密码保存在本地凭据存储或钥匙串，便携版随数据保存。
- 本地凭据使用免主密码的 version 2 格式，解锁信息随数据保存，不提供防止他人读取整个数据目录的隔离；旧格式需重新配置，保存新凭据前不覆盖原文件。

## 放手一搏：解除限制后的风险

这是把最后一道枷锁亲手斩断的终极档位：本地历史的脱敏不能阻止上述发送，也不能撤回已经传出的内容。切回受限档位后，后续上下文使用脱敏历史重建，但这不等于模型服务已经收到的数据被删除。脱敏无法识别所有未知秘密。

## 保护边界

这层检查不是服务器上的操作系统沙箱，无法证明任意外部程序、符号链接、未知凭据文件或任意混淆脚本都不会访问秘密。若需要这种强隔离，必须在服务器上使用独立低权限账号和文件访问隔离。已有历史文件不会被本次修复删除或重写。

## 操作授权

| 档位 | 命令授权 |
| --- | --- |
| 按配置执行 | 按风险规则自动执行、单次确认、双次确认或禁止 |
| 帮我批准 | 自动批准单次确认；双次确认仍需手动，禁止规则生效 |
| 完全放行 | 自动批准单次和双次确认；禁止规则和凭据访问限制生效 |
| 放手一搏 | **解开最后的枷锁，踏入高风险领域**：跳过 Agent-shell 的命令审批、禁止规则、任务策略检查和凭据访问限制 |

设置页选择默认档位，终端底部可以为当前连接临时覆盖；重新连接后恢复跟随设置。

审批只绑定本次调用的最终命令；命令改写后风险升高会再次申请所需授权，执行前还会重新检查规则和档位。切换权限后，等待审批的命令不能沿用旧授权执行。拒绝后本条命令不执行，本轮任务结束；点击“停止 Agent”会停止任务继续行动。

“完全放行”和“放手一搏”可以自动回答已授权命令中可识别的是/否提示，但执行时的授权档位必须与当前档位一致。密码和其他文本仍通过输入区填写。

已经提交给服务器的操作不会因切换档位或停止 Agent 自动撤销。使用步骤见 [Ash 使用手册](USER_GUIDE.zh-CN.md)。

## 回归检查

`yarn test:native-agent`、`yarn test:security:boundary-http`；隔离 Electron/SSH 验证：`yarn test:native-agent:ssh`。所有测试使用本机模拟服务和测试凭据。
