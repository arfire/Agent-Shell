# 终端与 Agent 修复说明

## 使用方式

- 终端直接输入 Shell 命令；Vim、补全和命令历史由远端处理。
- 底部输入框发送 Agent 请求，结果在同一区域显示。
- 右键打开普通复制／粘贴菜单。没有选中文字时，复制项不可用。旧的右键直接粘贴配置也按菜单处理。
- 历史记录自动换行；阅读旧内容时不会被新输出强行滚到底部。

## 原因与修改

1. **Agent 卡住**：原实现把命令放进交互式 PTY，状态查询可能打开分页器，程序不退出就无法拿到结束标记。现改为同一 SSH 连接上的独立非 PTY exec 通道，关闭标准输入，设置常见分页器为 `cat`，并加入 120 秒超时及独立取消处理。
2. **Vim 与粘贴**：移除 Agent 对交互终端输入的接管及提示符重绘。剪贴板统一处理 LF、CRLF、CR；Vim 等全屏程序保留换行、缩进和末尾空白，不应用 Shell 的换行转空格设置。右键在 xterm 清除选区或向远端报告鼠标事件之前处理。
3. **历史错乱**：不再把历史重新写进当前终端。记录全屏程序的进入提示，省略其光标重绘画面；普通输出先处理回车重绘、退格及行内删除。显示使用可换行的文字区域，并按新增事件增量更新。
4. **SSH 钩子**：运行时不再安装登录 Shell 钩子，不修改启动文件，不注入 base64 初始化命令。当前 russh API 未暴露 SSH `exit-status`，因此每次独立 exec 仍有短小的退出码封装；它随进程结束，不进入交互终端。
5. **Agent 行为**：提示词要求只做用户明确请求的事，使用最少必要命令，结果明确后立即停止；普通状态查询不延伸为修复、巡检或联网研究。移除已失效的自动命令识别设置入口。

## 执行边界

每次 Agent 命令是独立进程，`cd`、环境变量和别名不会继承可见终端或上一条命令。使用绝对路径，或把 `cd` 和依赖它的命令放在同一次调用中。Vim 等交互程序仍在普通终端使用。

停止／超时关闭的是 Agent 执行通道，不代表所有远端子进程都已终止。缺少退出状态时明确报错，不报告成功。已经丢失控制信息的旧历史无法还原成完整 Vim 画面。

## 验证

Windows、Node 22.20.0：

- `scripts/ash-build.ps1`：全部插件、应用和导出类型构建通过；存在仓库已有的 webpack 警告。
- `node scripts/test-native-agent.cjs`：58 项通过，包含拆包 UTF-8、stderr、退出码、缺失状态、超时、取消、历史过滤和换行粘贴。
- `node scripts/test-ai-reliability.cjs`：28 项通过；修正了旧测试中未提供权限服务的模拟对象。
- `node scripts/test-native-agent-docker.cjs`：隔离 OpenSSH 容器中的 Bash、Zsh、Fish 均通过。实际验证 Vim 打开时 Agent 执行、右键菜单复制、中文多行粘贴后的文件内容、停止后再次执行、窄窗口历史布局。
- 受影响的执行、输入和界面文件 ESLint 检查通过。全仓库检查另有既有问题，不将其计作本次修复通过项。

测试使用独立应用数据目录、临时容器和模拟模型，没有连接用户服务器或调用付费模型。

后续补充了真实鼠标键盘黑盒测试，发现并修复审批按钮被历史区域挤出窗口的问题。审批或输入表单出现时优先显示其内容。原生右键菜单、系统剪贴板、Vim 复制撤销、执行超时、断线重连、多标签隔离和重启恢复等结果见 [黑盒测试记录](AGENT_BLACKBOX_TESTS.zh-CN.md)。新增的 `yarn test:agent:blackbox` 包含 8 个可重复场景，已通过；它需要先启动独立测试夹具。
